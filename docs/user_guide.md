# Jesture 사용 설명서

웹캠 앞에서 손을 움직이면 PC 의 키가 눌리는 프로그램입니다. 스와이프 → 다음 창, 주먹 → 창 목록, 손가락 튕기기 → 선택처럼
동작마다 키를 붙여 두고, 손바닥을 잠깐 보여 주면 인식이 시작됩니다.

앱 안에서도 같은 내용을 볼 수 있습니다: 왼쪽 사이드바 맨 아래 **도움말**.

---

## 1. 3분 빠른 시작

### 1-1. 설치 (한 번만)

| 순서 | 할 일 | 명령 / 위치 |
|---|---|---|
| 1 | 저장소 받기 | `git clone -b hwangsoon https://github.com/Spice7/jesture_project` |
| 2 | 파이썬 패키지 설치 (처음 5~10분, 약 3GB) | 저장소 폴더에서 `uv sync --locked` |
| 3 | 모델 파일 2개 복사 (팀 드라이브에서) | `models\gru_gesture.pt`, `models\gru_gesture.json` |
| 4 | (선택) 정적 포즈 게이트 모델 | `models\yolo_gate.pt` — 없으면 게이트 없이(항상 열림) 동작 |

`uv` 가 없으면 `py -3.12 -m pip install uv` 로 먼저 설치합니다. 자세한 기기 세팅은 `docs/setup_windows.md`.

### 1-2. 실행

```powershell
uv run python main.py            # 연습 모드 (키를 누르지 않음) — 처음엔 이걸로
uv run python main.py --live     # 처음부터 실제 키 입력
uv run python main.py --camera 1 # 카메라가 여러 개면 번호 지정
```

`python` 만 치면 Windows 스토어 안내가 뜨는 기기가 있습니다. 항상 `uv run python` 으로 실행하세요.
카메라는 **한 프로그램만** 써야 합니다 (수집기, realtime_demo 등을 같이 켜면 화면이 1 fps 로 느려집니다).

### 1-3. 첫 화면에서 할 일 3가지

| 단계 | 할 일 | 확인 |
|---|---|---|
| 1 | 사이드바 아래 **실제 키 입력** 스위치 켜기 (연습만 하려면 그대로) | 빨간 알림 "실제 키 입력이 켜졌습니다" |
| 2 | 손바닥을 카메라에 **2초** 보여 주기 (게이트 열기) | 홈의 게이트 카드가 초록 "열림 — 인식 중" |
| 3 | 제스처 하기 (§3) | 홈 아래 카드가 빛나고 오른쪽 위에 "실행: …" 알림 |

게이트 모델(`yolo_gate.pt`)이 없으면 2단계는 건너뜁니다. 게이트가 항상 열려 있습니다.

## 3. 제스처 하는 법

공통 규칙: **손바닥이 카메라를 향하게**, 동작 사이에 **0.5초 이상** 잠깐 멈추기, 손 전체가 화면 안에 들어오게.

### 3-1. 동적 제스처 (GRU 모델이 판정)

| 제스처 | 이렇게 | 이렇게 하면 안 됨 | 팁 |
|---|---|---|---|
| **왼쪽 스와이프** ⇦ | 편 손을 **자기 왼쪽**으로 손바닥 하나 이상 휙 밀기 | 화면을 보고 화면 왼쪽으로 밀기 (반대 방향이라 안 잡힘) | 헷갈리면 홈의 "거울처럼 보기"를 켜세요. 화면에서 손이 오른쪽으로 흐르면 맞습니다 |
| **주먹 쥐기** ✊ | 편 손을 화면 안에 멈춘 뒤 쥐고, **쥐자마자 내리기** | 쥔 채로 0.8초 넘게 버티기 (게이트를 닫으려는 주먹으로 봄) | 화면 밖에서 들어오며 바로 쥐면 못 잡습니다. 편 손이 먼저 보여야 합니다 |
| **손가락 튕기기** ✦ | 엄지+중지를 붙였다가 확실히 튕겨서 떨어뜨리기 | 붙인 채 가만히 있기, 검지까지 접기 | 튕긴 뒤 검지가 펴져 있어야 합니다. 튕기는 순간 바로 판정됩니다 |

### 3-2. 정적 포즈 (YOLO 게이트, 유지 시간이 트리거)

| 포즈 | 하는 일 | 방법 |
|---|---|---|
| **손바닥** | 인식 시작 (게이트 열림) | 편 손바닥을 카메라 정면으로 **2초** 유지. 보라색 막대가 다 차면 열림 |
| **주먹** | 인식 끝 (게이트 닫힘) | 주먹을 **2초** 유지 |
| **세 번째 포즈** | 키 매핑의 "세 번째 포즈"에 붙인 키 (기본 Win+D) | 게이트가 열려 있을 때 **2초** 유지 |

유지 시간은 설정 페이지에서 1~5초로 바꿀 수 있습니다 (기본 2초). 앱을 켜면 게이트는 **닫힘**으로 시작합니다.
닫혀 있는 동안 동적 제스처는 판정·기록만 하고 키는 누르지 않습니다.

## 4. 키 매핑 바꾸기

키 매핑 페이지. 바꾸는 즉시 `gestures.json` 에 저장되고 인식에 반영됩니다.

| 방법 | 언제 | 하는 법 |
|---|---|---|
| **① 직접 녹화** | 원하는 단축키를 알 때 | 키 칸 클릭 → "키 조합을 누르세요…" 상태에서 조합 누르기 (예: Ctrl+Shift+T). Esc 취소, Backspace 지우기 |
| **② 기능 고르기** | 단축키는 모르고 "다음 슬라이드" 같은 이름만 알 때 | "기능 고르기 ▾" 목록에서 선택 (창 / 미디어 / 발표 / 브라우저 / 편집 / 기타) |
| **③ 프리셋** | 용도별로 4개를 한 번에 바꿀 때 | 맨 위 프리셋에서 고르고 **적용** |

프리셋 5개:

| 프리셋 | 스와이프 | 주먹 | 튕기기 | 세 번째 포즈 |
|---|---|---|---|---|
| 창 전환 (기본) | Tab (다음 창) | Ctrl+Alt+Tab (창 목록) | Enter (창 선택) | Win+D (바탕화면) |
| 발표 (PowerPoint) | → (다음 슬라이드) | Esc (쇼 끝) | F5 (쇼 시작) | B (화면 검게) |
| 음악·영상 | 다음 곡 | 음소거 | 재생/일시정지 | 이전 곡 |
| 브라우저 | Ctrl+Tab (다음 탭) | Alt+← (뒤로) | F5 (새로고침) | Ctrl+T (새 탭) |
| 바탕화면 | Alt+Tab (직전 창) | Win+D (바탕화면) | Win+Tab (작업 보기) | Win+E (탐색기) |

그 밖의 버튼: **Win** 체크(Win 키는 키보드로 잡히지 않아 체크로 붙임), **이름** 칸(홈 카드와 알림에 표시), **눌러보기**(지금 그 키를 한 번 누름),
**기본값**(창 전환 프리셋 값으로), **지우기**, **사용** 스위치(끄면 동작 없음, 다시 켜면 직전 키 복원).

## 5. 발표 · 시연 체크리스트

| 순서 | 확인 |
|---|---|
| 1 | 카메라를 쓰는 다른 프로그램(수집기, Teams 등)이 꺼져 있다 |
| 2 | `uv run python main.py` 로 켜고, 사이드바에 "카메라 0 연결됨" 이 보인다 |
| 3 | 화면 오른쪽 위 fps 가 20 이상이다 |
| 4 | 설정 → 게이트 정보에 `yolo_gate.pt` 와 GPU/CPU 가 표시된다 (없으면 "항상 열림"으로 시연) |
| 5 | 키 매핑 페이지에서 프리셋을 골라 **적용**했고, 겹치는 키 경고가 없다 |
| 6 | 연습 모드에서 세 동작을 한 번씩 해 보고 홈에 확신도 0.9 이상이 나온다 |
| 7 | 제어할 창(PPT, 브라우저)을 앞에 두고 나서 **실제 키 입력**을 켠다 |
| 8 | 손바닥 2초로 게이트를 열고 시연. 끝나면 주먹 2초로 닫는다 |
| 9 | 발표장 조명·거리에서 미리 한 번: 손이 화면의 1/4 이상 크기로 보이게 |

시연 습관: 손바닥은 카메라 쪽으로, 주먹 명령은 쥐자마자 내리기, 스와이프는 자기 왼쪽으로, 명령 사이 0.5초 이상.

## 6. 문제 해결

| 증상 | 원인 | 해결 |
|---|---|---|
| "카메라 0 를 열 수 없습니다" | 다른 프로그램이 카메라 사용 중, 또는 번호가 다름 | 다른 프로그램 종료 → 설정 → 카메라 번호 바꿔 **다시 연결**. 노트북 내장은 보통 0, USB 웹캠은 1 |
| 화면이 1 fps 로 느리거나 깨짐 | 두 프로그램이 같은 카메라를 쓰는 중 | 하나만 켠다 |
| 스와이프를 해도 "동작 아님" | 방향이 반대 (화면 왼쪽으로 밀었음) 또는 너무 짧음 | **자기 왼쪽**으로, 손바닥 하나 이상 거리. "거울처럼 보기"로 방향 확인 |
| 주먹 명령이 실행되지 않음, 기록에 `held fist` | 주먹을 0.8초 넘게 쥐고 있어 "끝내려는 주먹"으로 봄 | 쥐자마자 내리기. 편 손이 먼저 화면 안에 보여야 함 |
| 튕기기가 "동작 아님", 기록에 `no release` | 엄지·중지가 충분히 떨어지지 않음, 검지가 접힘 | 확실히 튕겨서 떨어뜨리고 검지를 편 채로 |
| 게이트가 안 열림 (보라 막대가 안 참) | 손바닥이 정면이 아니거나 너무 작음, 유지 시간이 김 | 손바닥을 정면으로 크게, 막대가 찰 때까지 유지. 설정에서 유지 시간을 줄임. 급하면 "YOLO 게이트 사용"을 끄고 다시 시작 |
| 키가 앱 창이나 엉뚱한 창에 눌림 | 키는 **앞에 있는 창**에 들어감 | 제어할 창을 클릭해 앞에 두고 나서 제스처. 앱 창은 옆으로 |
| 인식은 되는데 키가 안 눌림 | 연습 모드, 게이트 닫힘, 또는 확신도가 문턱(0.8) 미만 | 실제 키 입력 켜기 → 게이트 열기 → 설정에서 문턱을 0.7 로 |
| 기록에 `직전 명령 직후라 무시` | 명령 사이 간격이 0.5초 미만 | 동작 사이에 잠깐 멈춘다 |

## 7. 자주 묻는 질문

**Q. 왼손도 되나요?**
됩니다. 데이터는 오른손으로 모았지만 실측에서 왼손 스와이프도 인식됐습니다. 다만 방향은 똑같이 "자기 왼쪽"입니다.

**Q. 카메라에서 얼마나 떨어져야 하나요?**
손이 화면의 1/4~1/2 크기로 보이는 거리(팔을 반쯤 편 정도)가 가장 좋습니다. 멀어도 잡히지만 스와이프는 그만큼 크게 해야 합니다.

**Q. 게이트가 꼭 필요한가요?**
아닙니다. `models/static/v3.pt` 가 없거나 설정에서 "YOLO 게이트 사용"을 끄면 항상 열린 상태로 동작합니다.
게이트는 손을 무심코 움직였을 때 키가 눌리는 걸 막는 안전장치입니다.

**Q. 바꾼 키는 어디에 저장되나요?**
저장소의 `gestures.json`. 앱을 다시 켜도 유지됩니다. 지우면 기본값(창 전환 프리셋)으로 돌아갑니다.

**Q. 인식이 잘 안 될 때 가장 먼저 볼 것은?**
홈의 "모델 확률" 막대와 "지금 인식" 아래 한 줄 메시지입니다. "상식 검사에서 걸러짐: …" 이면 동작 모양이 기준에 못 미친 것이고,
"확신도가 낮아 무시" 면 문턱을 낮추거나 동작을 더 또렷하게 하면 됩니다. 기록 페이지에 같은 내용이 남습니다.
