# 동적 제스처 GRU 학습 실험 기록 (2026-09-05)

발표용 정리. 데이터 수집 → 검수 → 학습 → 평가까지 오늘 한 일을 순서대로 적었다.
비전공자도 읽을 수 있게 비유를 섞었고, 숫자는 전부 실제 실행 결과다.

## 0. 한 장 요약

- 4명(p002, p003, p004, p006) + 담당자 시험 데이터로 **총 855개** 시계열 샘플을 모았다. 형식·규약 검수 통과.
- GRU 모델을 **"한 사람을 통째로 빼고 학습 → 그 사람으로 시험"** 방식으로 4번 평가했다 (시드 3개씩).
- **결과: 처음 보는 사람 정확도 GRU 평균 96.4%, 룰 기반 평균 97.3%** (되감기 증강 채택 후. 증강 전 94.6%).
  깨끗한 기본 동작은 if문 몇 줄짜리 룰도 잘 맞힌다. 하지만 **룰은 p004 처럼 예상 밖 동작("주먹 쥔 채 움직이기")이 들어오면 무너지고(95.3%, no_gesture 재현율 71%), GRU 는 버틴다(99.1%).**
- GRU 의 약점은 **no_gesture(아무것도 아님) 판정**이다. 사람마다 "아무것도 안 함"의 모습이 달라서 학습에 없던 스타일이 오면 흔들린다. 데이터 다양성 문제이고, 최종 모델은 4명 전부를 학습에 넣으므로 이 표보다 좋아진다.

## 3. 평가 방법 (왜 이렇게 나눴나)

### 3-1. 시험 공부 비유

| 묶음 | 역할 | 비유 |
|---|---|---|
| 학습(train) | 답을 보며 배움 | 평소 문제집 |
| 검증(val) | 학습을 언제 멈출지 결정 (EarlyStopping) | 모의고사 |
| 시험(test) | 학습이 끝난 뒤 한 번만 채점. 발표에 쓰는 점수 | 수능 |

### 3-2. 사람 단위 분할 (leave-one-person-out)

같은 사람의 데이터를 학습과 시험에 섞으면 점수가 부풀려진다(내 손을 외웠으니까).
그래서 **한 사람을 통째로 시험용으로 빼고**, 다른 한 사람을 모의고사로, 나머지를 학습에 쓴다.
이걸 4명 각각에 대해 반복하면 "처음 보는 사람에게 얼마나 통하나"를 정직하게 알 수 있다.

```
실험 1:  시험 p002 | 모의고사 p003 | 학습 p004+p006+user00
실험 2:  시험 p003 | 모의고사 p004 | 학습 p002+p006+user00
실험 3:  시험 p004 | 모의고사 p006 | 학습 p002+p003+user00
실험 4:  시험 p006 | 모의고사 p002 | 학습 p003+p004+user00
```

### 3-3. 시드 3개

학습에는 무작위(초기 가중치, 데이터 섞기)가 들어가 매번 점수가 조금 다르다.
한 번 결과는 운일 수 있으니 **3번 돌려 평균 ± 표준편차**로 적는다.

### 3-4. 비교 대상: 룰 기반 baseline

딥러닝을 쓴 이유를 보이려면 "그냥 규칙으로 하면 안 되나"에 답해야 한다. 규칙은 이렇다 (`gesture/baseline.py`):

1. 손바닥 중심이 손바닥 크기의 1배 이상 이동했으면 → `swipe_left`
2. 아니고, 손가락끝~손목 거리가 시작 대비 30% 이상 줄었으면 → `make_fist`
3. 둘 다 아니면 → `no_gesture`

파라미터 0개, 학습 없음. GRU 와 **같은 시험지**로 채점한다.

### 3-5. 모델

| | GRU (우리) | 비고 |
|---|---|---|
| 입력 | (30프레임, 63 = 21관절 × xyz) | 정규화된 좌표 |
| 구조 | GRU 64 → Dropout → GRU 64 → Dropout → Dense 32 → Dense 3 | |
| 학습 파라미터 | 51,907 | LSTM 동급 구조보다 약 24% 적음 |
| 프레임워크 | **PyTorch 2.14** (09-06 저녁 TensorFlow/Keras 에서 이식. 팀 통일) | 초기화를 Keras 와 맞춤(입력 Glorot, 순환 직교) |
| 학습 | Adam, EarlyStopping(val_loss, patience 12), ReduceLROnPlateau, 최대 80 epoch, 증강 x3 | 실제로는 13~21 epoch 에 멈춤 |
| 학습 시간 | **15~28초 (노트북 CPU)** | GPU 불필요 |
| 추론 | 약 2.5 ms / 샘플 (Keras 68 ms) | 실시간 충분 |

### 4-2. 룰이 무너진 경우: p004 (GRU 승)

p004 의 no_gesture 35개는 전부 "주먹을 쥔 채 손을 이리저리 움직이기"다.

```
룰 기반 / p004 시험          GRU / p004 시험 (시드 0)
             예측 →                       예측 →
실제      swipe fist  none      실제      swipe fist  none
swipe_left  100    0     0      swipe_left  100    0     0
make_fist     0   76     0      make_fist     0   76     0
no_gesture   10    0    25      no_gesture    0    0    35   ← 전부 정답
             ↑ 움직였으니 스와이프?
```

룰은 "많이 움직이면 스와이프"라고만 보니 **주먹이 움직여도 스와이프**라고 한다.
GRU 는 "편 손 모양 + 한 방향 이동"을 함께 배웠기 때문에 속지 않았다.
**→ 발표 포인트: 규칙은 우리가 미리 생각한 경우만 처리한다. 사람이 바뀌어 예상 밖 동작이 오면 규칙을 또 손으로 고쳐야 한다. 모델은 데이터를 추가하면 된다.**

### 4-3. GRU 가 무너진 경우: p006 (룰 승)

p006 을 시험으로 뺐을 때 GRU 는 p006 의 no_gesture 47개 중 **23개를 `make_fist` 로** 오답했다 (시드 0).
틀린 23개의 내용: 편 손 정지 14, 주먹 정지 6, 편 손 살짝 움직임 2, 기타 1.

왜? 학습에 쓴 p002·p003·p004 의 no_gesture 는 짧은 정지(p003) 또는 움직이는 주먹(p004)이 대부분이라,
p006 의 "1.6~2.4초 길게 가만히 있는 편 손"은 **학습에서 본 적 없는 스타일**이었다.
룰은 "안 움직이고 손가락 변화 없음 → no_gesture" 라 이런 경우를 쉽게 맞힌다.

**→ 이건 모델 결함이 아니라 no_gesture 데이터가 사람마다 좁다는 문제다.** 최종 시연 모델은 4명 전부를 학습에 넣으므로 4가지 스타일을 모두 보게 되고, 이 실험 표보다 좋아진다.

### 4-4. 최종 시연 모델 (4명 전부 학습)

실력 측정이 끝났으니, 가진 데이터를 **전부** 넣어 실제로 쓸 모델 하나를 만들었다. 시험용을 남기지 않으므로 이 모델의 "처음 보는 사람" 점수는 없고, §4-1 의 실험 점수(평균 95%)가 근거다.

| | 값 |
|---|---|
| 학습 데이터 | 4명 + user00, 727개 + 되감기 no_gesture 295개 = 1,022개 (증강 x3 → 4,088개) |
| 검증(멈출 시점 판단) | 무작위 128개 (학습한 사람들의 데이터) |
| 학습 | 20 epoch, 59초 (CPU, PyTorch) |
| 검증 정확도 | **100%** (128개 전부. 룰 기반 98.4%) |
| 저장 | `models/gru_gesture.pt` + `gru_gesture.json` (라벨 순서, 입력 크기, 반전 여부, framework, reverse_neg 기록) |

```
GRU / 검증 128개                 룰 / 검증 128개
             예측 →                          예측 →
실제      swipe fist  none      실제      swipe fist  none
swipe_left   53    0     0      swipe_left   53    0     0
make_fist     0   55     0      make_fist     0   55     0
no_gesture    0    0    20      no_gesture    2    0    18
```

p001, p005 데이터가 오면 같은 명령으로 다시 만든다 (§6). 이 파일이 실시간 인식 루프에 들어가는 모델이다.

### 4-7. 되감기 증강: "펴기"와 "복귀"를 no_gesture 로 가르치기 (09-06 23시, 채택)

실시간 실측에서 모델이 **주먹을 펴는 동작을 make_fist 1.00** 이라 하고, 스와이프 **복귀(오른쪽 이동)** 도 가끔 swipe 라 했다. 학습 데이터에 펴기 6개, 복귀 0개뿐이라 배운 적이 없어서다. 상식 검사가 막고는 있었지만 모델 자체를 고치는 방법으로, **명령 클립을 시간 역재생해 no_gesture 학습 샘플로 추가**했다 (`dataset.reversed_negatives`, 학습 세트에만, 클립의 50%).

- make_fist 되감기 = 쥔 손 → 편 손 (펴기). 손목이 제자리라 되감아도 자연스러움.
- swipe_left 되감기 = 편 손이 오른쪽으로 (복귀). 가속 곡선은 뒤집히지만 부정 예시로는 충분.

| 설정 | p002 | p003 | p004 | p006 | **평균** | no_gesture 재현율 평균 |
|---|---:|---:|---:|---:|---:|---:|
| 없음 | 94.6 | 92.4 | 99.1 | 92.4 | 94.6 | 75.6 |
| 주먹만 되감기 | 97.3 | 92.9 | 97.8 | 97.0 | 96.3 | 85.6 |
| **주먹+스와이프 되감기 (채택)** | 97.8 | 92.4 | 98.1 | 97.2 | **96.4** | **85.2** |

(`--reverse-neg both --reverse-frac 0.5`. 사람 단위 분할·시드 3 동일. 명령 두 개의 정확도는 유지되고 no_gesture 만 올랐다. p003 시험은 변화 없음 — p003 의 no_gesture 는 전부 정지라 펴기·복귀와 무관.)

## 5. 정직한 해석과 발표 멘트

**Q. 룰이 평균으로는 더 높은데, 그럼 딥러닝을 왜 쓰나?**

1. 우리 제스처 3개는 **의도적으로 단순하게 설계**했다(한 방향 스와이프, 주먹). 단순한 문제는 규칙도 잘 푼다. 이건 규칙이 뛰어난 게 아니라 문제가 쉬운 것이다.
2. 룰의 임계값(이동 1.0, 손가락 30%)은 **우리 데이터를 보고 사람이 맞춘 값**이다. 사실상 사람이 손으로 "학습"시킨 것이라 공정한 비교에서 유리하다.
3. **예상 밖 입력에서 갈린다.** p004 사례에서 룰은 no_gesture 의 29%를 명령으로 오인했다. 시연에서 오작동 한 번이 가장 치명적인데, 그 위험을 데이터로 줄일 수 있는 쪽은 모델이다.
4. **확장성.** 제스처를 4개, 5개로 늘리면 룰은 규칙을 새로 짜고 서로 안 겹치게 조정해야 한다. 모델은 데이터 50개를 더 찍으면 된다. 실제 우리 파이프라인은 라벨 추가가 config 한 줄이다.

**Q. GRU 를 고른 이유?**
- LSTM 과 같은 계열이면서 파라미터 24% 적고 학습·추론 빠름. 이 데이터 규모(수백~천 개)에서는 성능 차이가 시드 편차 안에 들어온다. (팀원 LSTM 결과와 나란히 놓을 것. 팀원 LSTM 은 별도 PyTorch 코드 — 분할 방식·시드를 맞춰야 비교 가능)

**Q. 성능을 더 올리려면?**
- no_gesture 다양화가 1순위: 복귀 동작(오른쪽으로 되돌리기), 손 들여오기/내리기, 긁기 등을 4명 모두 추가.
- 스와이프 클립 시간 역재생을 no_gesture 학습 예시로 추가하면 복귀 동작을 안 찍고도 보강 가능(검증 필요).
- no_gesture 클래스 가중치 상향.
- 실시간에서는 모델 판정 + 신뢰도 임계값 + cooldown + 연속 프레임 검증을 겹쳐 오작동을 막는다.

**결론 (09-06 23:25 기준, 튜닝 종료)**: 실시간 루프는 시연 가능 수준. 남은 정확도 위험은 "학습에 없던 no_gesture 스타일"(§4-3)과 손바닥 방향 규약이며, 둘 다 시연 방식(손바닥 보이고, 정해진 동작만, 주먹은 쥔 뒤 0.3초 멈춤)으로 관리한다. 모델 밖의 안전장치 세 겹: 확신도 0.8 · 구간 시작 기준 cooldown 1.2초 · 상식 검사.

## 5-2. 프레임워크 이식 (09-06 저녁)

팀(YOLO, 팀원 LSTM)이 PyTorch 라 우리 GRU 도 TensorFlow/Keras → PyTorch 로 옮겼다. 바뀐 파일은 `gesture/model.py`, `gesture/training.py` 둘뿐(전처리·감지기·안전장치·스크립트는 그대로). 구조·파라미터 수(51,907)·학습 설정(Adam, EarlyStopping 12, ReduceLROnPlateau) 동일.

| | Keras | PyTorch (기본 초기화) | PyTorch (Keras 초기화 맞춤) |
|---|---:|---:|---:|
| 4인 leave-one-out 평균 | 95.1 | 91.1 | **94.6** |
| 추론 시간 / 샘플 | 68 ms | 2.5 ms | 2.5 ms |

기본 초기화(모두 균등분포)로는 no_gesture 재현율이 떨어졌고, Keras 와 같은 초기화(입력 Glorot uniform, 순환 가중치 직교, 편향 0)로 맞추자 시드 편차 안에서 같아졌다. RNN 은 초기화에 민감하다는 교과서적 사례. 저장 형식 `.keras` → `.pt`. TensorFlow 는 pyproject 에 남아 있으나 우리 코드는 더 이상 부르지 않는다.
